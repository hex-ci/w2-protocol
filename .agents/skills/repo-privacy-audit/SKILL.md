# w2-protocol 提交前隐私审计

本仓库为公开仓库，入库内容（git 跟踪的代码、文档、注释、提交信息）有匿名化纪律，口径见仓库根 `AGENTS.md`。**每次改动入库文件后、汇报「完成」前，跑一遍本审计**。

## 何时跑（必做，不是可选）

- 任何会入库（git 跟踪）的代码、文档、注释、字典改动**完成前**；
- 用户提出「清理隐私/敏感信息」「检查能不能公开」时；
- 用户 commit 之前（代理不 commit，只交付已过审的工作树）。

## 快速执行

```bash
python3 .agents/skills/repo-privacy-audit/scripts/audit.py --root .
```

- 缺省自动加载同目录 `references/w2-extra.local.json`（项目词表）与 `references/w2-keep.local.json`（保留项过滤）；也可显式 `--extra` / `--keep` 指定。
- 退出码非 0 = 有疑似残留需处置。
- 词表文件缺失时脚本不报错、跳过对应类别——**项目特有残留会漏检，报告时必须注明「词表缺失」**。

## 三条铁律

1. **工作树干净 ≠ 历史干净。** `git log -S <token>` 能在旧提交里找到已从工作树清掉的内容。仓库为 public 时，工作树清理只是第一步——必须主动提醒用户还有历史暴露面（处理选项：转 private / 干净首提交新建仓库 / `git filter-repo` 重写；外部动作由用户执行）。
2. **边界 = 是否入库。** gitignore 的本地档（`captures/`、`.hermes/plans/`、`.identity.local.json`、`.env`、`*.local.json`）可以保留真实数据，不必清理、也不必因此提问；约束只针对 git 跟踪 + 待提交的文件。
3. **分拣，不要一刀切。** 残留分三类：必改 / 需用户拍板 / 已拍板保留。第三类最容易犯错——把拍板保留项当残留改掉，会直接破坏本地运行。

## 流程

### 1. 定范围

```bash
git ls-files                                  # tracked
git ls-files --others --exclude-standard      # 待提交的未跟踪
```

审计范围 = tracked ∪ untracked（非忽略）。**新写的文件最容易漏**（未跟踪）——`git grep` 只看 tracked，别拿它当唯一扫描器。

### 2. 值对照优先于正则（关键）

从本地真值档提取**具体值**做全树字面搜索，比猜正则可靠得多（命中即确凿）：

- `.identity.local.json` → userId / username / wst / installID / appKey / WTGT / gameHost / serverName
- `.env` → 渠道、版本、任务 ID、设备 IP
- 状态缓存（`.transport_route.local.json`、`.train_state.local.json`）→ 城池 ID 列表
- 已知坐标对 / 军官 ID / 资产数值（来自会话记忆或 `captures/`）

真实数据常藏在「示例」与「自检桩」里（曾实测：组帧自检用例混入真实 userId）——纯正则扫不到，只有值对照能抓。

### 3. 分类扫描

脚本内置类别：实测日期 / 产品名 URL 编码形态 / 厂商域名 / UA 指纹 / 凭据形态 / 可滥用措辞 / 邮箱 / 内网 IP / 手机号 / 个人路径。项目特有类别由 `w2-extra.local.json` 提供（真实城名与城 ID 段、军官名、坐标形态、活动专名、错误文案全句）。

### 4. 分拣与处置：按「特异性」分四级

判据是**特异性**——能否反向定位到具体厂商或具体游戏。

- **必改**：真密钥、厂商域名、指向具体游戏的渠道/版本真值、真实标识（城名/城 ID/坐标/资产/玩家标识）、实测日期、示例/自检里的真实值、可滥用措辞。→ 真值迁本地 `.env`，代码留中性。
- **必改（客户端/服务端原文案）**：UI 专名、错误提示原文、本地化描述全句也是识别信息，一律改描述性表述（写功能语义，不抄原文串）。**优先用协议状态或协议字段替代文案匹配**：拒绝原因常可由「拒绝后重读状态查询命令看实体状态」判定；实体定位改用服务端下发的类型/分组 ID 字段（名称随版本变、ID 稳定）。确实只能靠文案区分时才保留功能匹配串并登记 keep 表。已中性化的串要加进 extra 词表做回归防护。
- **必改（含服务端契约字段名）**：厂商词根出现在**服务器下发的字段名**里时——**按大方针「匿名化优先于可用性」，一律环境变量化、且不留代码缺省**（见 §5「契约字段名的环境变量化」）。
- **保留**：协议常量（端口号）、通用第三方渠道名（华为/果盘等）、中立代号（`W2_` 前缀）、公开史实名（兵种/装备名）、已拍板项。写进 `w2-keep.local.json` 由脚本过滤。**若 keep 词表缺失导致这些出现在残留清单——不要改动代码，补词表即可。**
- **不加评**：gitignore 本地档（`.env`、`*.local.json`、`captures/`）。

**判级要点**：

- **端口号不是厂商标识**：各服统一、wire 可观测的端口（游戏服长连接端口等）属协议常量——保留，必要时补注释「协议常量，非厂商标识」。删掉会让文档与实现失去可对照性。
- **通用第三方渠道名可保留**：华为、果盘这类第三方 SDK，不指向游戏厂商或具体游戏，在协议里就是「渠道登录验证」的功能语义。判据：指「某个游戏」还是「一个通用平台」。
- **中立代号不折腾**：项目自取代号（`W2_` 前缀、`w2-*` 文件名）不指向任何厂商，改名波及大量 env 变量与文件名，收益为零——保留。

### 5. 中性化写法

- **契约字段名的环境变量化（大方针：匿名化优先于可用性）**：厂商词根出现在**服务器下发的字段名**里时，不能改名（那是服务端契约，改了取值变 `undefined`），但也**不留代码缺省**——改为由 `.env` 提供键名，代码按配置取值：
  ```js
  // config.js：无缺省，真值走 .env
  userIdField: get('W2_SSO_USERID_FIELD', ''),
  // 使用处：按配置名取值
  const username = desDecrypt(sso[config.sso.userIdField]);
  ```
  **必须同时**：① 把该键名纳入启动期完整性校验（缺项即报错，与其它未配置项同一提示路径）；② 本地 `.env` 写真实键名并实测取值可用；③ `.env.example` 加该键（留空 + 说明）；④ 文档里用描述性表述，**不写键名字面**。
  **为什么不留缺省**：留缺省等于词根仍在仓库里（只是从逻辑位置挪到常量位置），匿名化目标落空。不留缺省的代价是「不配置就跑不了」——按大方针这个代价值得付。
  **与功能匹配串的区别**：匹配服务器下发文本的字符串**默认不该留**——先尝试用协议状态或协议字段替代（拒绝原因常可由「重读状态查询命令」判定；实体定位改用服务端下发的类型/分组等 ID 字段，比名称稳定——名称随版本/月份变，ID 不变）。确实无替代又必须区分时，才保留原串并登记 keep 表。判断依据：能否用协议状态、协议字段或配置注入替代而不改变功能语义。
- 具体值 → 配置项引用（如 `W2_SSO_*` / `W2_LOGIN_*`），真值迁本地 `.env`；一次性迁移不留兼容层（不加「先读 env 再回退旧常量」的回退读取）。
- **环境变量化的收尾纪律**（缺一则本地必坏）：① 本地 `.env` 写真值并**实测生效**（打印长度/非空验证，不打印内容）；② 代码缺省改中性占位或空串；③ 加**启动期配置完整性校验**，缺项时给可操作的报错（否则以模糊的「连接失败」收场）；④ 更新 `.env.example` 注释为「必填」。
- 指纹类（User-Agent）：**代码缺省放通用形态**；真机形态走本地 `.env` 模板，支持 `{clientVer}` 占位符保持与登录帧版本号同源。
- 客户端/服务端文案（UI 专名、错误提示原文、本地化描述）→ 描述性表述，保留可辨识特征即可（写功能语义，不抄原文串）。
- 文档替换后**回读上下文**——中文成句容易替换得不连贯（曾出现「超发返回（超限时提示升级司令部）。每笔运输…」这类残句）。

### 6. 验证（缺一不可）

```bash
npm run lint && npm run test          # 代码类改动
node lib/w2build.js                   # 组帧自检
npm run genapi -- --write             # 改了文档模板时复查生成器
```

再加：

- **重跑扫描**：目标类别零残留、保留项仍在原处；
- **真实链路**：能跑就跑一次登录或业务 `--dry`，证明没把运行必需的东西改坏；
- **指纹类比对**：改 UA 这类值后，与改动前的字符串做**逐字节比对**（本地行为完全一致才算安全）。
- **行为等价性对拍**：`git worktree add /tmp/old HEAD` + 软链 `node_modules` + 拷身份/缓存档，新旧紧连各跑一次（加 `--no-progress`），剥数字 + 表格只取前 N 列做结构指纹比对（数值会自然漂移，逐字节 diff 必假红）。

### 7. 汇报格式

1. 按类别列改动（文件 + 处数）；
2. 明确「按拍板保留了什么」——避免用户以为漏了；
3. 扫描前后对照数字；
4. 说明未提交（用户自己 commit）；
5. public 仓库有历史残留时单独提醒。

## 历史清理规范

**工作树干净 ≠ 历史干净**；反之也要先证明历史到底脏不脏——**用值对照法精确定位，不要凭 token 命中数下结论**：

1. **精确性校验**：短 token（如 5 位 userId）会与代码里的数字常量偶然撞上，造成假阳性。判定凭据泄露必须满足**长度下限**（<6 字符的值直接跳过并注明「太短无法判定」）+ 词边界。实测案例：`userId` 命中的其实是旧自检桩里的数字常量巧合，工作树已无该值。
2. **历史身份/资产扫描**：把本地档（`.identity.local.json`、`.env`、状态缓存）里的**具体值**逐个 `git log --all -S<value>` 搜索（真城名、城 ID、凭据、坐标）。凭据值搜索**只报「命中/未命中」，不打印值**。
3. **重写方式选择**：
   - **压成单个初始提交**（`git checkout --orphan` + 单次 commit）：**零历史残留**的首选——连旧提交信息里的词一起消失，操作最简单可复现。适合「历史不重要、最新代码不变即可」。
   - **filter-repo 逐提交重写**：保留开发脉络，但提交信息本身仍需逐条审，残留面更大。
4. **重写前必备份**：`git bundle create <backup> --all`（可完整回滚）+ 工作树 tar。重写会改变全部 commit hash、与 origin 冲突，**必须强推**——按用户惯例把 `--force-with-lease` 命令交付用户执行，不自行强推。
5. **必须告知的边界**：public 仓库重写历史**无法召回已被 clone / 被搜索引擎或第三方镜像缓存的旧内容**——用户必须知情，不能承诺「彻底清理」。若在意，可选删远程仓库重建。

## 本地词表（不入库）

两个词表均为 `*.local.json`（gitignore），**换机器 / 新 clone 后需重建**：

- `references/w2-extra.local.json` —— 项目特有情表。重建方法：让 agent 扫描本地档（`captures/`、`.identity.local.json`、`.transport_route.local.json`）自动汇总真实城名 / 城 ID 段等，生成后**只留在本地**。**厂商词根也放这里**（从本地真值档与 git 历史里提取的厂商域名词根）——绝不能写进 tracked 的 `audit.py` 或本文档，否则等于把词根重新入库（**写文档时用描述性表述，不要抄词根本身**）。
- `references/w2-keep.local.json` —— 已拍板保留项过滤。重建方法：按上文「保留（勿动）」的类别总结；新增拍板保留项时同步补进该文件，否则下次审计会把保留项报成残留（或被下一个 agent 误「修」）。**真值迁走 `.env` 后要同步瘦身**：原「代码缺省保留」条目已失效（缺省已中性化），应改为「服务器下发字段名（契约）」「功能匹配串」这类仍然成立的条目。

## 坑

- **部分 ripgrep 版本不支持 `-E` 参数**（被当成编码参数报 `unknown encoding`）——用默认正则语法，中文直接写。
- **扫描必须覆盖未跟踪文件与提交信息**（`git log --format=%B` 扫一遍）；历史里的旧提交改不了，只能重写历史。
- **别把拍板保留项改成脱敏占位**：文档侧清理与代码缺省保留是两回事，后者是用户决议。
- **功能匹配串默认不留**：能靠协议状态判定的一律改用状态（更稳）；确实只能靠文案区分的才留原串并登记 keep 表。
